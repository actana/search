# TASK-003 — `search` schema and migrations

Drizzle schema `packages/search/src/db/schema.ts` under `pgSchema('search')`, migrations
in `packages/search/drizzle/` generated by drizzle-kit and applied at boot by
`db/migrate.ts` (`drizzle-orm/postgres-js/migrator`), `CREATE EXTENSION IF NOT EXISTS
vector` guarded.

Tables (Part 2 ERD; columns otherwise identical to Studio's `packages/db/schema.ts`
lines ~2602–3088 so the phase-4 move is `SET SCHEMA` + renames):
- `paired_client(id, label, platform, cert_serial, cert_fingerprint, scopes,
  kb_ids jsonb, status, last_seen_at, revoked_at, created_at)`
- `pairing_code(code pk, paired_client_id?, label?, expires_at, consumed_at,
  attempts, created_at)` — the short-code session store (Control keeps it in memory /
  SQLite; here Postgres)
- `model_endpoint(id, paired_client_id, kind, provider, template, model, dimension,
  base_url, key_ciphertext?, source 'local'|'mirrored', external_id?, label,
  created_at, updated_at)`
- `knowledge_base` — Studio columns with `workspace_id → paired_client_id`,
  `user_id → owner_id` (plain text), `embedding_endpoint_id`/`inference_endpoint_id`
  → FK `model_endpoint`
- `knowledge_base_tag_definitions`, `embedding` (the v1 shared table, tag slots),
  `document` (with `connector_id text` plain), `document_embed_batch`, `kb_cluster`,
  `kb_keyword`, `embedding_keyword`, `document_keyword`
- per-KB partitions `kb_embedding_<sha256(kbId)[0..12]>` created by the lifted
  `ddl.ts` in schema `search`, HNSW index included
- `webhook(id, paired_client_id, url, secret_ciphertext, events jsonb, created_at)`
- `webhook_delivery(id, webhook_id, event_id, status, attempts, last_error, created_at)`

Also: `schema_version` exposed by `GET /v1/capabilities`. Integration test that runs the
migrations on an empty database twice (idempotent) and creates/drops a partition.

## Outcome

Done on `feat/bootstrap-and-lift`. Fourteen tables under `pgSchema('search')` with Studio's columns and index names unchanged, generated migrations in `packages/search/drizzle/`, applied at boot by `db/migrate.ts` behind `CREATE EXTENSION IF NOT EXISTS vector`; the integration suite migrates an empty database twice, proves two migrators starting at once are safe, and creates and drops a partition through the lifted `ddl.ts`, gated on `SEARCH_TEST_DATABASE_URL`. `knowledge_base.paired_client_id` is NOT NULL (ADR 0003), every raw statement qualifies its table by schema, and `docs/migration-from-studio.md` records what phase 4 actually has to do — `SET SCHEMA` is not the whole of it.
